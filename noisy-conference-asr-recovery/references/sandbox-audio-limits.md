# Grok 沙箱：录音文件到不到磁盘

## 两种「上传」不是一回事

用户在聊天里上传 m4a 后，系统通常会：

1. 跑内置 ASR，把带说话人标签的文本塞进 `<AUDIO id="…" filename="…" duration="…">`；
2. **有时**把原文件拷到 `/workspace/attachments/`。

第 1 步成功 **不保证** 第 2 步成功。没有磁盘文件就无法 ffmpeg / 能量扫描 / Whisper。

内置 ASR 自带 VAD。同一份嘈杂长录音再传一次，`<AUDIO>` 里的时间轴空洞 **几乎不变**。不要把「再传完整文件」当成恢复手段。

## 实测（本场）

| 体积 / 时长 | 结果 |
|---|---|
| ~7.3 MB / ~8 分钟短片 | 进 `/workspace/attachments`，可二次识别 |
| ~68 MB / ~73 分钟 | 进附件，可切片处理 |
| ~100 分钟以上整场（尾缀 3、4） | 聊天有完整 `<AUDIO>`（含同样的假空白），**原 m4a 不进附件** |

反复「请再传完整尾缀 3」不会改变结果。要改成 **只传空白段切片**。

## 用户允许访问原音频

用户说「我允许你访问原音频」时，不是新开了一条下载通道，也不是还要先征求同意。

1. 再找一次：本次附件、项目文件、磁盘上同名或同时长的 m4a / mp3 / wav。
2. 找到了：只对空白段做二次识别（高通 + 增益，关 VAD）。已经转清的部分不要重跑。
3. 没找到：用一句话说明整场原件没有进来，请把空白段裁成 10–16 分钟。不要把整场再要一遍。

## 操作

每次开转写先跑：

```bash
ls -lah /workspace/attachments/
find /workspace /tmp -iname '*.m4a' -o -iname '*.wav' 2>/dev/null
```

对用户说明时不要提容器/路径内部名，只说：

- 聊天里的自动转写已经收到；
- 原音频没有进入可处理环境；
- 请把空白段前后各留约 10 秒，裁成 10–16 分钟再传。

## 切片请求模板

> 请只导出 `30:20–42:20`（约 12 分钟）再上传，不要整场。电脑可用：
>
> ```bash
> ffmpeg -ss 00:30:20 -t 00:12:00 -i "源.m4a" -c copy yebin_30-42.m4a
> ```
>
> 手机用任意剪辑 App 裁同一区间即可。
